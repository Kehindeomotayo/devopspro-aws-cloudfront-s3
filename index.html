Our Philosophy

Beyond "just make it work"

Enterprise DevOps demands the why behind every tool and architectural decision. That mindset helps learners move beyond copying commands into understanding trade-offs.

Technical ThinkingSecurity Default The WhyCloud ArchitectureTeam-Centric
🧠

Critical or Technical Thinking

Before any task execution how does this benefit the organization, your teammates, making every task and project efficient in the real world.

🔐

Security Default

Think security. Security should be taken into consideration on every task or project you are handling, talk about CI/CD Pipeline, RBAC, IAM, Identity Center, etc.

🌎

The Why

Understanding why each tool exists, and the problem they solve. Examples of these are Docker, Kubernetes, cloud providers AWS, Azure & GCP etc.

🏗️

Cloud Architecture

Designing cloud environments with security, cost, reliability, and team workflows in mind.

🤝

Team-Centric

Great DevOps engineers make their teammates' lives easier. We simulate that.

Programme Curriculum

The full curriculum

Live instructor-led training built around real projects, cloud delivery, infrastructure as code, and CI/CD workflows.

Git & GitHubLinuxBashPythonDockerPostgreSQLGitHub ActionsGitLab CITerraformAWS
Week 1–2

Git, GitHub & Collaboration Standards

  • Why Git exists and the versioning problems it solves
  • Git internals: objects, refs, and how commits work
  • Branching strategies: GitFlow and trunk-based development
  • Enterprise pull request standards and code review culture
  • GitHub: pull requests, issues, security settings, GitHub CLI
Week 3–4

Linux, Bash Scripting & Python for Automation

  • Linux navigation, permissions, users, processes, and networking basics
  • Bash scripting: variables, loops, conditionals, functions, cron jobs
  • Python for DevOps: data types, functions, modules, file I/O
  • Writing automation scripts for repeatable operational tasks
  • Error handling, exit codes, and logging best practices
Week 5–6

3-Tier Web App — Frontend, Backend & Database

  • Why DevOps engineers need to understand what they deploy
  • Frontend basics: HTML, CSS, and JavaScript
  • Backend REST API with Python (Flask) or Node.js
  • Connecting frontend to backend with HTTP, JSON, and environment variables
  • PostgreSQL schema design, queries, and app connectivity
Week 7–8

Docker & Containerising the 3-Tier App

  • Why containers exist and where they fit in modern delivery
  • Dockerfile best practices and multi-stage builds
  • Docker Compose for frontend, backend, and PostgreSQL
  • Container networking and volumes for persistence
  • Container security: non-root users, image scanning, and secrets
Week 9–10

AWS Deep Dive & DevOps Services

  • Core services: EC2, VPC, S3, RDS, ECS, EKS, Route53, CloudFront
  • IAM deep dive: least privilege, roles, policies, security groups, NACLs
  • CloudWatch monitoring and Cost Explorer for operational visibility
  • Deploying the 3-tier app to AWS end-to-end
  • Security and cost considerations for cloud-hosted applications
Week 11–12

Terraform & Infrastructure as Code

  • Why Terraform matters in repeatable infrastructure delivery
  • State management, remote backends, and reusable modules
  • Variables, outputs, providers, and environment configuration
  • Provisioning AWS infrastructure with clear naming and structure
  • Reviewing infrastructure changes before deployment
Week 13–14

CI/CD with GitHub Actions & GitLab CI

  • Pipeline design principles: fast feedback, quality gates, and release safety
  • GitHub Actions: workflows, secrets, environments, reusable actions
  • GitLab CI: stages, caching, artefacts, and self-hosted runners
  • Blue-green and canary deployment concepts
  • Security scanning: SAST, DAST, and dependency auditing in pipelines
Week 15–16

Robust End-to-End Portfolio Project

  • Build a complete project that brings together Git, Linux, scripting, Docker, AWS, Terraform, and CI/CD
  • Deploy the 3-tier application through a structured delivery workflow
  • Document architecture, setup steps, deployment decisions, and troubleshooting notes
  • Prepare a portfolio-ready repository that shows both implementation and reasoning
  • Final review: explain the project clearly from code to infrastructure to deployment
